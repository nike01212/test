# 盤後新聞標的整理

需求見 [PRD-MVP.md](PRD-MVP.md)，實作順序見 [PLAN.md](PLAN.md)，免費額度見 [FREE-TIER.md](FREE-TIER.md)。

架在 Cloudflare 免費方案上：Workers（網站和後端）＋ D1（資料庫）。

## 檔案在哪裡

| 路徑 | 內容 |
| --- | --- |
| `src/index.ts` | 後端入口：每個請求都先檢查有沒有登入，再決定要給什麼；測試站在這裡換掉左上角的網站名稱 |
| `src/auth.ts` | 群組密碼、登入 cookie、密碼輸錯太多次的限制 |
| `src/api.ts` | 清單的 API：貼入、刪除、處理待確認、改日期、改標籤、延續性觀察、收盤比對 |
| `src/tradingDay.ts` | 所屬交易日規則（09:00 前歸當天，其他歸下一個開盤日）、前後一個開盤日 |
| `src/calendar.ts` | 伺服器用的休市行事曆：`holidays.json` 加上 `closures.json` |
| `src/closing.ts` | 收盤比對：清單上的個股在前一個交易日收盤有沒有漲停（送出新聞後、排程、「現在比對」都用這個）；排程收盤後存上櫃收盤快照 |
| `src/closingData.ts` | 證交所、櫃買中心收盤資料的網址和解析（只取需要的那幾檔，不把整份資料轉成物件） |
| `src/streak.ts` | 連續被提到幾個交易日 |
| `public/` | 網頁本身（登入頁、今日清單頁） |
| `public/matcher.js` | 在瀏覽器裡找出文字提到的個股（伺服器 CPU 有限，比對放在這裡做） |
| `public/split.js` | 預覽：把混貼的網址、memo 拆成一則一則 |
| `public/links.js` | 網址清理（拿掉追蹤參數、App 推廣連結），瀏覽器和伺服器共用 |
| `public/extract.js` | 從新聞網頁取出標題和內文（在瀏覽器裡做） |
| `public/ocr.js` | 圖片文字辨識（Tesseract.js，在各人瀏覽器裡做，圖片不上傳） |
| `public/tagger.js` | 標籤和國際大廠合作對象的判斷（在瀏覽器裡做，送出前判斷好） |
| `src/fetchPage.ts` | 替瀏覽器抓新聞網頁（`/api/fetch`），不解析、原樣轉回 |
| `public/export.js` | 匯出：拆 A、B 組、複製用的代號、.txt、CSV、元大、三竹和富邦 e01 電腦版的匯入檔 |
| `public/marks.js` | 勾選、「已加入」標記和上傳的三竹清單的存放（只存在各人的瀏覽器） |
| `public/watch.js` | 延續性觀察要顯示哪幾檔（清單上前一個交易日收盤漲停的，加減手動的） |
| `public/data/stocks.json` | 上市櫃代號與名稱，由 `npm run update-data` 產生，不要手改 |
| `public/data/holidays.json` | 證交所休市日，由 `npm run update-data` 產生，不要手改 |
| `public/data/closures.json` | 臨時休市日（例如颱風假），證交所的行事曆不會補，手動維護 |
| `public/data/name-rules.json` | 比對規則：別名、容易混淆要「待確認」的詞、要略過的一般詞彙（手動維護） |
| `public/data/tags.json` | 標籤清單和關鍵字（手動維護） |
| `public/data/big-companies.json` | 國際大廠名單：全球市值前 100 名（有資料日期和來源）加上其他常見的知名企業，含常見中英文別名（手動維護） |
| `public/.assetsignore` | 不要上傳到網站的檔案（Mac 的 Finder 自動產生的 `.DS_Store`） |
| `scripts/update-data.mjs` | 從證交所、櫃買中心抓上面兩個資料檔 |
| `scripts/otc-snapshot.mjs` | 在家裡的電腦補某一天的上櫃收盤快照（`npm run otc-snapshot -- 2026-10-22`，見「收盤資料從哪裡來」） |
| `tests/` | 比對、標籤與大廠、交易日規則、匯出分組、勾選存放、收盤資料解析、連續天數的測試（`npm test`）；`tests/fixtures/` 是 2026/10/22 證交所、櫃買中心的真實收盤資料（只留幾檔） |
| `migrations/` | 資料庫的表格定義 |
| `wrangler.jsonc` | Cloudflare 的設定（上面是正式站，`env.staging` 是測試站） |

## 第一次上線

在終端機進到這個資料夾（`dailynews`）後，依序執行：

1. 登入 Cloudflare（會打開瀏覽器；沒有帳號就先免費註冊，不用綁卡）：

   ```bash
   npx wrangler login
   ```

2. 部署網站。第一次會問你要用什麼 workers.dev 子網域（網址的一部分，例如 `你取的名字.workers.dev`），也會自動建立資料庫：

   ```bash
   npm run deploy
   ```

3. 設定群組密碼。輸入時畫面不會顯示字，打完按 Enter；設定完馬上生效，不用重新部署：

   ```bash
   npx wrangler secret put GROUP_PASSWORD
   ```

完成後打開 `https://dailynews.你的子網域.workers.dev`。

## 測試站

2026/10/24 起正式站給群組使用，**所有修改都先部署到測試站**，發起人看過、同意了才部署正式站。

| | 正式站 | 測試站 |
| --- | --- | --- |
| 網址 | https://dailynews.tw-notes-8317.workers.dev | https://dailynews-staging.tw-notes-8317.workers.dev |
| 部署 | `npm run deploy` | `npm run deploy:staging`（先套用資料庫 migration 再部署） |
| 資料庫 | `dailynews`（大家真的資料） | `dailynews-staging`（測試資料，隨便貼、隨便刪） |
| 群組密碼 | `npx wrangler secret put GROUP_PASSWORD` | `npx wrangler secret put GROUP_PASSWORD --env staging`（另外設，要和正式站一樣也可以） |
| 左上角的網站名稱 | 盤後新聞標的整理 | 盤後新聞標的整理 - 測試站（`wrangler.jsonc` 測試站的 `SITE_BRAND`） |

- 程式、網頁、排程（清圖片全文、收盤比對）和正式站一模一樣，只有資料庫和密碼分開，設定在 `wrangler.jsonc` 的 `env.staging`。
- 測試站的網址不用貼到群組，只給要幫忙測試的人。測試資料只放測試站，不要再放進正式站。
- 兩個網站共用同一個 Cloudflare 帳號的免費額度（每天 10 萬次請求；排程整個帳號 5 個，現在正式站、測試站各 2 個），見 `FREE-TIER.md`。

## 日常操作

- **改群組密碼**：重新執行第 3 步。改完之後所有人都會被登出，要用新密碼重新登入。
- **更新網站**：先 `npm run deploy:staging` 部署到測試站，發起人確認後再 `npm run deploy` 部署正式站（有新的資料庫 migration 也會一起套用）。`migrations/` 多了新檔案時，先執行 `npx wrangler d1 migrations apply DB --remote` 再部署，新程式才不會有幾秒讀不到新欄位。
- **更新代號清單和休市日**：`npm run update-data`，再 `npm run deploy`。有新股上市、或證交所公布明年休市日（通常在年底）之後跑一次。行事曆還沒公布的年份，系統只會排除週末和元旦，交易日檢查會提醒。
- **颱風假等臨時休市**：證交所的行事曆不會補上颱風假，要在 `public/data/closures.json` 的 `closed` 加一行（例如 `"2026-10-23": "薔琵颱風停止交易"`），再 `npm run deploy`。加了之後那天貼的會自動歸到下一個開盤日，收盤比對、延續性觀察、連續被提到都會跳過那天。已經歸到那天的資料不會自動搬，要在「這天貼入的資料」按「改日期」移過去。
- **調整比對規則**：改 `public/data/name-rules.json`，再 `npm run deploy`。例如某個常見詞一直被誤判成股票，就加進 `ignore`；某檔的常見叫法對不到，就加進 `aliases`；已經下市、併進別家的公司（例如矽品），加進 `merged`。
- **調整標籤**：改 `public/data/tags.json`（加標籤、加關鍵字），再 `npm run deploy`。寫法看檔案開頭的 `_說明`；改完可以先跑 `npm test`，格式寫錯會直接告訴你哪裡。
- **更新國際大廠名單**：大約每半年打開 `public/data/big-companies.json` 裡 `source` 的網址，照新的排名增減 `companies` 裡的公司、改 `updated` 日期，再 `npm run deploy`。超過半年沒更新，網頁最下面那行會寫「超過半年沒更新了」。不在前 100 名、但新聞常出現的公司（例如高通、索尼）放在 `others`，想到就可以加。
- **收盤比對沒有跑成功**：延續性觀察上會寫原因（例如「證交所的收盤行情還沒公布」「連不到 www.twse.com.tw」），按「現在比對」可以馬上再跑一次。都比對過了還想整頁重抓，按「重新比對」（1 分鐘內只能按一次）。
- **寫「收盤後沒有存到上櫃的收盤資料，要請發起人用家裡的電腦補」**：那天的上櫃收盤快照沒存成，網站已經查不到那天的上櫃股。用家裡的電腦（要登入過 wrangler）在專案資料夾跑 `npm run otc-snapshot -- 2026-10-22`（換成那一天；測試站加 `--staging`），它會從櫃買中心抓那天的收盤行情、寫進資料庫，並列出那天收盤漲停的上櫃股；再到那一頁的延續性觀察按「現在比對」。
- **本機測試**：`npm run dev`，打開 http://localhost:8787 。本機用的測試密碼在 `.dev.vars`（不會上傳）。要手動觸發排程，用 `.claude/launch.json` 的 8788 設定（有 `--test-scheduled`）打開 http://localhost:8788/__scheduled?cron=0+19+*+*+* （清圖片全文）或 http://localhost:8788/__scheduled?cron=30+6,8,10,12,14,23+*+*+* （上櫃收盤快照和收盤比對，比的是本機「現在」；加 `&time=` 毫秒可以假裝是別的時間，例如 `&time=1793057400000` 是 2026/10/27 07:30）。本機的上櫃收盤快照可以用 `npm run otc-snapshot -- 2026-10-22 --local` 補（本機連得到櫃買中心）。要比對過去某一天，用清單頁的「現在比對」，或在網頁的主控台呼叫 `/api/closing`（`{"date": "2026-10-22"}`；加 `"dryRun": true` 只抓資料、不寫進資料庫，這時還可以加 `"codes": ["2465", "3691"]` 指定代號、不讀清單；正式站測試就用這個，不會留下資料）。
- **自動測試**：`npm test`（比對規則、標籤與大廠、交易日規則、匯出分組、勾選存放、網址清理、拆分、內文擷取、辨識結果整理、收盤資料解析、連續天數，也會檢查標籤、大廠、臨時休市三個設定檔的格式）

## 版面

- 手機、平板直放：一欄，由上到下是日期、貼上、預覽、待確認、延續性觀察、匯出、個股清單。
- 電腦（畫面寬 1100 像素以上）：左右兩欄，左邊貼上和預覽，右邊是清單（待確認、延續性觀察、匯出、個股、這天貼入的資料）。左欄會停在畫面上，往下捲清單時貼上框一直看得到；預覽很長時在左欄裡面捲動。
- 深色模式下按鈕和勾選是金色（#E6C261），淺色模式是紅色。

## 貼上與預覽

- **能貼什麼**：網址和文字可以混在一起貼，一次很多則也可以（例如從 LINE 複製一整段）。圖片可以直接貼上、拖曳到網頁上，或按「加入圖片」從相簿選。
- **怎麼拆**：按「預覽」後，每個網址各成一則，網址前面或同一行的標題當成它的說明。連續的文字段落算同一則；空一行之後以【】《》〈〉◆■ 等符號開頭的，當成另一則。LINE「儲存聊天」匯出的紀錄，一則訊息就是一則。網址旁邊的文字很長（例如附了來源連結的 memo），整段當成文字，不另外抓網址。
- **拆錯了**：可以「合併到上一則」、刪除，或把類型在「網址」和「文字」之間切換。兩個網址不能合併成一則。
- **抓錯的個股**（2026/10/26 發起人要求）：網址類那一則的「找到 N 檔」，每一檔旁邊有「×」，按了那一檔直接消失、不會送出（例如內文出現「三竹」兩個字，被認成三竹資訊）。不能復原，按錯就刪掉整則重貼。拿掉之後標籤和合作對象當作沒提到那檔重算，只剩一檔時整則內容都算它的。全部拿掉的那一則留在預覽裡、不會送出，不要的話按那一則的「刪除」。之後再補貼內文、重新抓取，拿掉的也不會回來；把類型改成「文字」就不再拿掉。文字類、圖片類沒有「×」，直接改字；「待確認」的也沒有，用下一點的方式回答。
- **預覽裡回答待確認**（2026/10/26 發起人要求）：網址、文字、圖片三類都可以。點「▸ 待確認：三星」展開，跟清單上的「待確認」一樣有原因、那一句、「是 5007 三星」「不是個股」，也可以搜尋改成其他個股。選了某一檔就變成一般的個股；「不是個股」就不送出。跟「×」一樣不能復原，標籤和合作對象照結果重算。不回答的照舊送出，到清單上的「待確認」再處理。
- **預覽裡改標籤**（2026/10/26 發起人要求）：標籤那一行有「改標籤」，畫面和清單上的一樣（可以勾、自己填、搜尋合作對象）。改的是這一則的每一檔：勾掉的從每一檔拿掉、加的每一檔都加上，沒動的照原本（各檔可能不一樣）。按「完成」才套用；還沒按「完成」的那一則先不送出，底下會寫「N 則標籤還沒按「完成」」。之後改字、補貼內文，改過的照樣套上。
- **網址整理**：自動拿掉分享參數（utm_、fbclid、from 等）和 App 下載、加好友之類的推廣文字與連結。經濟日報、鉅亨網、工商時報、Yahoo 股市的網址會整理成固定的寫法，所以同一篇只算一則：同一次貼的重複網址直接略過；同一天已經貼過的，預覽會標出來，送出時也會略過。
- **抓內文**：伺服器替瀏覽器去抓網頁、原樣轉回來，由你的瀏覽器取出標題和內文來比對個股。抓不到（網站擋掉、要登入或付費、找不到內文）會標「抓取失敗」，打開網址把內文複製貼進那一則就能送出；只抓到標題和摘要的也可以補貼。
- **圖片**：用 Tesseract.js 在每個人自己的瀏覽器裡辨識文字，圖片不會上傳，送出或刪除那一則之後就丟掉。第一次使用要從 jsDelivr 下載約 6 MB 的辨識程式和繁體中文字庫，之後瀏覽器會留著。辨識不準的地方可以直接改文字。圖片裡最大的字會當成標題（另外裁下來再辨識一次，比較準），標題上面那行（通常是版名和日期）當成出處，兩個都可以修改；找不到標題（例如字都一樣大的 memo 截圖）就用第一行當標題。辨識出來的全文也會存起來，清單上顯示「（圖片）出處」，全文預設收起來，點「辨識出來的全文」才展開。全文只留 180 天，之後每天自動刪掉（標題、出處、提到個股的句子還在）。實測工商時報版面截圖：中文字約 94% 正確，英文和數字比較差（CCD、TM4 常認錯），標題完全正確。
- **送出**：每一則都會先顯示找到哪些個股，以及標籤和合作對象。沒有個股的、重複的不會送出；抓取失敗又沒補文字的會留在預覽裡等你補。網址和文字只存標題、網址、提到個股的句子和每檔的標籤、合作對象；圖片另外存出處和辨識出來的全文。
- **預覽不會存**：預覽只在這個分頁裡，重新整理或關掉就不見（預覽還有東西時，瀏覽器會先提醒）。
- **這天貼入的資料**：清單最下面列出這天貼進來的每一則，新貼的在最上面（2026/10/24 發起人要求），可以改日期或刪除。

## 比對個股的規則

- 名稱來源：證交所、櫃買中心的官方簡稱，加上公司全名去掉「股份有限公司」「科技」等字之後的叫法（例如「全新光電」「日月光」），以及 `name-rules.json` 的別名。
- 名稱後面緊接代號（例如「台積電(2330)」「統一 1216」）就直接確定。
- **已經下市、併進別家的公司**（2026/10/26 發起人要求）：例如「矽品」2018 年併進日月光投控後下市，不在上市櫃清單裡。寫在 `name-rules.json` 的 `merged`（「矽品」→ 3711）就會算成日月光投控，匯出、收盤比對、連續被提到都算 3711。預覽上寫「3711 日月光投控（矽品）」，清單上名稱旁邊標「新聞寫「矽品」」。標記是看存下來的句子（每檔每則前 2 句）有沒有寫「矽品」。
- 標「待確認」的情況：容易和一般用語混淆的名稱（例如「統一」「創意」）、同一個名稱對到兩檔（「台南」和「台南-KY」）、名稱和括號裡的代號對不起來、括號裡的代號不在上市櫃清單（例如 ETF）。
- **漏掉的個股**（「手動新增個股」2026/10/23 拿掉了）：送出前在預覽那一則的文字裡補上名稱或「(代號)」，例如「台積電」或「(2330)」，馬上就會對到；網址類的按「自己補貼內文」再補。只打數字「2330」不算，免得金額、張數被誤認成代號。已經送出才發現漏了，就在「這天貼入的資料」刪掉那一則、重貼。某個叫法常常對不到，就加進 `name-rules.json` 的別名。以前手動新增的個股還在的話，卡片上寫「手動新增」，可以直接刪除。
- 只存標題、提到個股的句子（每檔每則最多 2 句，太長的句子只留前後一段）和每檔的標籤、合作對象。網址和文字不存全文；圖片例外，辨識出來的全文會存起來（2026/10/23 發起人決定，一則最多 2 萬字），所屬交易日超過 180 天的每天台北時間 03:00 自動刪掉（`wrangler.jsonc` 的 `triggers`）。

## 標籤與合作對象

- **什麼時候判斷**：送出前在預覽就判斷好（每則下面有一行「標籤：…　合作對象：…」），送出時和個股一起存。網址和文字不存全文，送出之後就不能重算，所以改了設定檔，已經送出的不會變；第 5 步上線之前貼的都沒有標籤，要的話手動加。
- **標籤**：內容出現 `tags.json` 裡某個標籤的任何一個關鍵字，就貼上那個標籤。標籤只描述內容，不代表利多或利空。目前有漲價、新訂單、營收創高、獲利創高、合作、供不應求、擴產、轉型、併購、調升目標價、6人說。
- **新訂單**（2026/10/23 由「訂單」改的）：只認明確寫出拿到新訂單的說法：接獲、拿下、取得、獲得、斬獲、搶下、贏得…訂單（或大單），新訂單、追加訂單、追單、急單、轉單，訂單湧入、上門、入袋。「訂單強勁」「訂單能見度」「在手訂單」講的是既有訂單，不算；「打入某某供應鏈」沒有直接說訂單，也不算；美國 ISM「新訂單指數」、「新訂單減少」不算。關鍵字只能看文字怎麼寫，新聞沒寫明是新的（例如只寫「訂單暢旺」）就判斷不出來。原本的「訂單」標籤（只要出現「訂單」兩個字就算）已經拿掉；正式站之前存下來的資料裡沒有「訂單」標籤，所以不用另外清。
- **6人說**（2026/10/23 加的）：內文有公司表示（中間可以隔幾個字，例如「公司今天表示」）、董事長、總經理、財務長、總裁、執行長。只看有沒有這些詞，所以別家公司的執行長（例如「輝達執行長黃仁勳」）也會算；央行總裁不算。
- **合作對象**：內容提到 `big-companies.json` 裡的公司（全球市值前 100 名，加上高通、索尼、美超微、OpenAI 等 40 家常見的知名企業；含常見中英文別名，例如「輝達」「NVIDIA」「NVDA」），清單上顯示「輝達（NVIDIA）」。台股（台積電、聯發科）本身就會出現在清單上，銀行和券商在新聞裡多半是外資研究報告（「大摩」「高盛」調升目標價），這兩類不比對。
- **算哪一檔的**：一則只提到一檔，整則內容都算它的；提到好幾檔（例如券商 memo 一行一檔），每檔只看提到它的段落，別檔的「調升目標價」不會貼過來。預覽時按「×」拿掉的個股不算在內（見「貼上與預覽」）。預覽上那一行是整則合起來的，每檔各自的標籤在送出後的清單上看（電腦上把滑鼠停在預覽的個股上也看得到）。
- **手動修改**：送出前可以在預覽裡改那一則的每一檔（見「貼上與預覽」）；送出後清單上每檔都有「改標籤」，可以勾選標籤、拿掉或加上合作對象。改的是這一天的這一檔：加的貼到提到它的每一則上，拿掉的從每一則拿掉。設定檔改名或刪掉的標籤，已經存下來的還會顯示，也可以在這裡拿掉。
  - 標籤可以自己填（設定檔裡沒有的也行，例如「手機鏡頭」），最多 20 個字。
  - 合作對象用搜尋的：打中文、英文、別名或美股代號都找得到（例如「nvidia」「高通」「SONY」），不自動比對的銀行、台積電也搜得到；名單裡沒有的公司，選「自己填「…」」就照打的字加上去。
  - 自己填的只加在這一檔，不會讓以後的新聞自動判斷；常用的請加進 `tags.json` 或 `big-companies.json`。
- **設定檔寫錯**：例如少了逗號，網頁會跳出「標籤設定讀取失敗」，清單和貼入照常能用，只是這段時間送出的沒有標籤。

## 匯出到自選

- **勾選**：清單上每檔都可以勾選。勾選和逐檔快速加入的「已加入」標記只存在各人的瀏覽器裡，依日期分開存，不會寫進資料庫，也不會跟到別台裝置。超過 90 天的紀錄會在打開網頁時自動清掉。私密瀏覽這類不能存資料的情況，頁面一樣能用，只是重新整理後勾選（和匯入的三竹清單）就不見了。
- **範圍**：可以選「當天全部」或「只匯出已勾選」，有勾選時預設是後者。待確認的個股不會匯出。
- **清單和匯出的順序不一樣**：清單上依加進清單的時間排，新的在前面（同一則裡的照原文順序；2026/10/23 發起人要求）。匯出照舊依被提到的則數由多到少排（則數一樣就依代號），複製、下載、逐檔加入都是這個順序。
- **分組**：60 檔以內只有一組，組名是月日（例如 1028）；超過 60 檔，照上面的順序每 60 檔切成一組：1028-A、1028-B……，A 組是被提到最多的（e點通每組最多 60 檔）。
- **格式**：複製代號（一行一個）、.txt（內容和複製的一樣）、CSV（代號、名稱兩欄）。CSV 開頭有 UTF-8 BOM，Excel 和 Numbers 打開中文才不會變亂碼。
- **券商電腦版的匯入檔**（2026/10/24 加的）：主清單的每一組另外有「下載元大檔」「下載三竹檔」「下載富邦檔」；延續性觀察那組只有「下載富邦檔」（2026/10/26 發起人要求加的），沒有元大、三竹。元大、三竹的格式照發起人拿到、確定能匯入的範例檔；富邦的照發起人從 e01 匯出的檔和實測。元大、三竹都沒有 BOM、換行 CRLF、最後一行也有換行。
  - 元大電腦版看盤：一個檔一組，一行「組名=代號,代號,…」，例如 `1028=2330,2317`，檔名是 1028-元大.csv。匯入後是新的一組（發起人試過沒問題）。
  - 三竹 Windows 電腦版：第一行 `PID,MTK`，接著 `G1,組名,代號,…` 到 `G5`，每行用空的欄位補到 30 欄（比較寬時每行一起加寬）。**匯入會把軟體裡的自選全部蓋掉**，所以可以先按「匯入三竹清單」上傳自己從三竹匯出的自選檔：下載時只把 G1 那一列整個換成這次的個股（組名照原本的），其他組照上傳的清單原樣寫回去（中文組名不管是 Big5 還是 UTF-8 都不會變亂碼）。沒上傳就是 G1 放個股、組名是日期（例如 1027），G2～G5 空白。
  - 上傳的三竹清單只存在這台裝置的瀏覽器，一直用到下次上傳；在三竹裡改過其他組的話，要重新匯出、再上傳一次。上傳的不是三竹的自選檔（第一行不是 `PID,MTK`、或沒有 G1）不會收。
  - 超過 60 檔：三竹每 60 檔一個檔（1027-三竹-1.csv、1027-三竹-2.csv），每個檔都只換 G1；60 檔以內是 1027-三竹.csv。
  - 還沒確認：一組 60 檔能不能一次匯進三竹（試過約 10 檔正常）。富邦e點通（手機）沒有拿到能匯入的範例檔，還是用複製代號或逐檔加入。
  - 富邦 e01 電腦版（2026/10/26 加的，核心是 XQ）：「下載富邦檔」是 e01 自己的自選股匯出檔格式（.dsl_DAQFAP，檔名 1027-富邦.dsl_DAQFAP），在 e01 用匯入自選股匯入。匯入後**最後面多一組，組名是網頁上的組名**（1027、1027-A、1027-延續性觀察），個股照匯出的順序；組名、組的位置要改就在 e01 裡自己改（發起人確認可以）。
    - 代號上市、上櫃**都加 `.TW`**（例如 `2330.TW`、`6488.TW`）；沒加的會變紅色不能用，`.TWO` 匯入時會被丟掉（發起人實測）。
    - 檔案是 OLE 複合文件（舊版 Office 檔那種），裡面每組一段 Big5 文字 `1,組的ID;組名,2330.TW,…`。e01 匯入時 ID 已經有的組整組略過（內建的自選一～六也改不到），所以每次下載都用新的 ID。組名用 Big5 寫：瀏覽器只會 UTF-8，所以用瀏覽器的 Big5 解碼反推編碼表，和 Windows 的 cp950 逐字比過，中文字全部一樣。
    - 原本另外有一行一個代號的 CSV，匯入後組名一律是「新組合」，發起人決定拿掉。
- **逐檔快速加入**：一次用大字顯示一檔。按「已加入，下一檔」會標記並前進，點代號可以複製。關掉再打開，會從第一檔還沒加入的接著開始。標記過的，清單和延續性觀察上會顯示「已加入自選」（只記在這台裝置的瀏覽器，別人看不到；要拿掉就在逐檔加入裡按「取消標記」）。

## 收盤漲停延續性觀察（以前叫續看清單）

- **延續性觀察是什麼**（2026/10/23 發起人說明後改的）：收盤後貼進來的新聞，會歸到下一個開盤日的清單；這一頁清單上的個股，如果前一個交易日收盤漲停（收盤價等於漲停價，盤中碰到漲停、收盤打開的不算），就自動出現在這一頁的延續性觀察。例如 10/22（四）收盤後貼的新聞歸到 10/27（二）（10/23 颱風休市、10/26 光復節補假都跳過），新聞裡 10/22 收盤漲停的個股就在 10/27 這頁的延續性觀察。所以自動加進來的，下面的新聞清單一定也有；新聞刪掉了，它也會跟著不見。
- **什麼時候比對**：送出新聞後，網頁會馬上要求比對新貼的個股（不用等排程，通常幾秒到十幾秒）；另外排程在台北 14:30、16:30、18:30、20:30、22:30、隔天 07:30 補比對還沒比對過的（例如待確認改好的、改日期移過來的），也順便存上櫃收盤快照（見下面）。比對過的不會重抓。前一個交易日還沒收盤（交易日 09:00～14:00 貼的）就等收盤後的排程。
- **畫面**：自動加進來的不另外標「收盤漲停」，手動加的標「手動加入」。還有個股沒比對到時會寫「還有 N 檔還沒比對」和「現在比對」按鈕；都比對完只留「重新比對」按鈕（整頁重抓，1 分鐘內只能按一次），滑鼠停在按鈕上看得到上次比對的時間。程式和資料庫裡叫 watch / watchlist。
- **手動加減**：可以手動加、也可以移出，大家看到的都一樣（存在資料庫，不是各人的勾選）。移出的不會因為重新比對又被加回來；手動再加一次就回來。
- **匯出**：延續性觀察要另外存成一組自選，所以匯出放在延續性觀察這一區裡（不在上面清單的匯出裡），組名是日期加「延續性觀察」（例如 1027-延續性觀察），可以複製代號、下載 .txt、CSV、逐檔加入。這一組不看個人的勾選，永遠是整份延續性觀察。
- **每日漲停紀錄**：每一檔比對過的收盤價、漲停價、有沒有漲停都存在資料庫的 `closes`（`hit = 1` 是收盤漲停），一直保留，之後要做「漲停後隔天續漲」的統計可以用。

### 收盤資料從哪裡來（2026/10/23 查證）

上櫃股先看 **上櫃收盤快照**（2026/10/27 加的，見下面），沒有快照的再用 **證交所「基本市況報導」即時報價系統**（mis.twse.com.tw），上市、上櫃都查得到，只查清單上那幾檔。它只有最近一個交易日的資料，所以比對過去的日子、或它連不上時，改抓 **交易所的每日收盤資料**（上市、上櫃分開抓，一邊抓不到另一邊照樣存起來）：

| 來源 | 收盤價 | 漲停價 |
| --- | --- | --- |
| 上櫃收盤快照（上櫃先看這個） | 排程收盤後從即時報價系統存的全部上櫃股；沒存成的，用家裡的電腦從櫃買中心補 | 同左 |
| 即時報價系統 | 最後一盤的成交價；最後一盤沒有成交（例如漲停鎖住、沒有人賣）就用最後一筆成交價 | 系統上的當天漲停價 |
| 上市每日資料（備案） | 證交所「每日收盤行情」（[MI_INDEX](https://www.twse.com.tw/zh/trading/historical/mi-index.html)），收盤後公布 | 證交所「股價升降幅度」（TWT84U），當天開盤前就公布 |
| 上櫃每日資料（備案，正式站抓不到） | 櫃買中心「上櫃股票每日收盤行情」 | 同一份資料「前一個交易日」那份的「次日漲停價」 |

- **兩種來源的數字一樣**：2026/10/22 實測 140 檔（上市 43、上櫃 97），即時報價系統的收盤價、漲停價和證交所、櫃買中心公布的全部一樣。那天證交所統計「股票收盤漲停 3 檔」，比對出來的也是麗臺、華經、暉盛-創這 3 檔。
- **為什麼先用即時報價系統**：它只回傳清單上那幾檔，資料很小。證交所的每日資料一份就有幾百 KB，正式站剛啟動時解析要 6～10 毫秒，快碰到免費方案每次 10 毫秒 CPU 的上限；改用即時報價系統之後是 2～3 毫秒。
- **櫃買中心擋掉雲端機房**：從 Cloudflare 連櫃買中心的網站、開放資料 API 都會被轉到錯誤頁（從家裡的電腦連正常），證交所沒有擋。所以在正式站上，上櫃只能靠即時報價系統，而它在下一個交易日早上就換成新的一天（2026/10/27 實測 07:5x 已經換了；颱風假、週末不換）。10/22 收盤後到 10/27 早上才貼的上櫃股因此比對失敗（「即時報價系統只有 10/27 的資料，改抓每日收盤資料也不行」），而且當時連上市股也一起失敗。
- **上櫃收盤快照**（2026/10/27 為了上面的問題加的）：排程收盤後（14:30 那次；沒成功就 16:30、18:30…再試）向即時報價系統查全部上櫃股（約 900 檔，一次 100 檔、查 9 次），收盤價、漲停價存成一份（資料庫的 `otc_snapshots`，一天一列約 22 KB）。之後才貼進來的上櫃股，不管隔了幾天都從快照比對，不用再連外面。存的時候全部解析約 2 毫秒 CPU。萬一那天的排程都沒存成（即時報價系統整晚連不上），延續性觀察會寫「收盤後沒有存到上櫃的收盤資料，要請發起人用家裡的電腦補」，照「日常操作」補（`npm run otc-snapshot`）。
- **即時報價系統有時候比較慢**：從 Cloudflare 連，實測要等 3～20 多秒才回應，所以會等到 30 秒，沒回應再試一次（等待不算 CPU）。按「現在比對」可能要等十幾秒。這個系統不是交易所正式公布的資料介面，哪天格式改了，清單頁會寫出原因，不會默默算錯。
- **漲停價直接用交易所的**，不自己算。交易所的已經算好除權息當天的參考價（自己用前一天收盤價算，除權息那天會算錯），也標出沒有漲跌幅限制的（新股上市前五天、外國成分 ETF，漲停價寫 9,999.95，這種不算漲停）。
- **參考：漲停價怎麼算的**：前一天收盤價（除權息時用調整後的參考價）× 1.1，不滿一個「升降單位」的部分捨去。升降單位依價格：10 元以下 0.01、10～50 元 0.05、50～100 元 0.1、100～500 元 0.5、500～1000 元 1、1000 元以上 5。證交所 2026/8 已決定 1000 元以上改成 1 元（預計最快 2027/7 實施），這也是我們不自己算、直接用交易所數字的原因之一。
- **什麼時候公布**：官方網頁沒有寫幾點。漲停價開盤前就有；收盤價在收盤（13:30）之後陸續公布。即時報價系統收盤後每一檔的資料時間都是 13:30:00（整天沒成交的也是），當天 14:00 以後查就當作收盤資料。送出新聞後馬上比對；排程在台北 14:30、16:30、18:30、20:30、22:30、隔天 07:30 存上櫃收盤快照、補比對，存過、比對過的不再抓。資料還沒公布、出錯時，延續性觀察會寫出原因。
- **資料不對就不比**：資料還沒公布會寫「還沒公布」，等下一次排程；欄位改名、日期不對會寫「資料格式變了」「日期不對」，不會默默算錯。用了每日收盤資料，比對結果後面會寫「用交易所每日收盤資料」。只比對到一部分時（例如上市的比對好了、上櫃的抓不到），比對到的照樣存起來、出現在延續性觀察，延續性觀察上寫「另外 N 檔沒有比對到」和原因，下次比對只補沒比對到的。到 18:30 都還沒有資料，多半是那天臨時休市（例如颱風假），請把日期加進 `closures.json`。

## 連續被提到

- 清單上每檔如果連續 2 個交易日以上都在清單上，卡片上會顯示「連續 N 天」。從那天往前一個開盤日、一個開盤日找，週末、休市日（含 `closures.json` 的臨時休市）直接跳過，不算中斷；哪一個開盤日的清單上沒有它就停。
- 以前「手動新增個股」加的也算（這個功能 2026/10/23 拿掉了）；待確認的不算。
- 最多算到 20 天（大約一個月），再多就顯示「連續 20 天以上」。每次打開清單都會算，D1 免費額度是算讀了幾列，所以不往前找太多。
- 那天要是沒人貼資料（清單是空的），連續就會斷掉。

## 安全設計

- 沒有輸入密碼前，除了登入頁以外的東西都拿不到（網頁和資料 API 都會擋）。
- 登入後保持 30 天，之後要重新輸入。
- 同一個網路位置 15 分鐘內輸錯 10 次，會暫時擋下。
- 「現在比對」同一天 1 分鐘內只能按一次（證交所對同一個來源短時間內太多次的請求會暫時擋掉，避免大家同時一直按）。
- 每個回應都帶 `X-Robots-Tag: noindex`，網頁裡也有 `<meta name="robots" content="noindex">`，搜尋引擎不會收錄。`robots.txt` 刻意不擋爬蟲，搜尋引擎才讀得到這個 noindex 標記。
- 替瀏覽器抓新聞網頁（`/api/fetch`）只抓一般網站：不抓本機、內部網路或直接寫 IP 的網址，轉址的每一步都會檢查；網頁超過 5 MB 或 10 秒沒回應就放棄。抓回來的網頁不會存起來。
