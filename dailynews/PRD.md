# PRD：新聞標的整理與自選股匯出網站（階段 1）

2026年10月23日 · @簡單

## 背景與目標

目標：讓約 30 人的投資朋友群，收盤後把新聞、券商 memo、報紙照片貼進網站，系統自動整理成「個股清單」，隔天開盤前能最快速地把個股加進券商 App 自選。

目前的痛點：

- 新聞很多，要自己消化並判斷是哪一檔個股。
- 要手動把每檔代號加進券商 App（戶頭在富邦、第一金、國泰，三家都沒有 Mac 版軟體；發起人用手機 App 下單）。
- 資料散在 LINE，沒有每日紀錄可以回頭查。

階段 1 成功的樣子：

- 貼入當天全部資料後，得到已去重、已對上代號的當日個股清單。
- 開盤前照清單逐檔快速加入富邦e點通自選，所花時間少於現在手動翻新聞。
- 每天資料自動歸檔，之後可以查歷史。

## 使用者與使用情境

使用者是約 30 位投資朋友，共用同一份每日清單，不需要完整的帳號系統。

- 每日節奏：收盤後蒐集個股公布的利多資訊 → 加入自選 → 隔天開盤後，若股價發動飆漲就第一時間買入。
- 系統不判斷利多或利空，由每個人自己判斷；系統只負責整理與呈現事實。
- 管理員是發起人：持有雲端帳號、管理群組密碼與費用。發起人使用 Mac mini，並用富邦e點通手機 App 開盤搶買。
- 其他朋友用哪家券商、哪個軟體目前未知，需要之後在群組做調查。
- 目前大家在 LINE 分享資料，網站上線後改成直接在網站輸入。

## 範圍與分階段

先只做階段 1；階段 2、3 先記錄需求，暫不開發。

| 階段 | 內容 | 前提 |
|---|---|---|
| 1 | 總入口、規則式整理、每日清單（超過 60 檔拆 A、B 組）、通用匯出、逐檔快速加入模式、資料保存與 7 天原文刪除、群組密碼 | 先開發 |
| 2 | 收盤漲停續看清單、連續被提到的累計統計 | 需要外部股價資料，階段 1 穩定後再做 |
| 3 | 富邦專用匯入格式，之後依券商調查再做其他家 | 取決於富邦電腦版是否支援匯入檔案 |
| 暫緩 | Windows 虛擬機測試、向富邦客服預檢 | 發起人決定先擱置 |

明確不做（第一版）：

- 系統判斷利多或利空。
- 在網站顯示即時報價（發起人要直接在券商 App 看盤與下單）。
- 匯入過去 LINE 裡的歷史資料，從上線當天開始記錄。
- 由 AI 生成摘要（改用規則式整理，保留日後開關）。

## 核心流程

從貼入資料到開盤前加入自選，共八步，每步都可以由人修正。

1. 在網站總入口貼上網址、文字、圖片，可以一次混貼。
2. 系統自動拆成一則一則，清掉網址的追蹤參數與 App 推廣文字，並顯示預覽（每則的類型：網址、純文字、圖片）。
3. 使用者確認，必要時手動合併或刪除，再送出。
4. 系統抓取網址內文（抓不到就標「抓取失敗」，改貼文字補上），圖片用文字辨識；網址去重。
5. 規則式整理：用官方名稱與代號清單比對個股，擷取含關鍵字的原文句子，貼上標籤，比對國際大廠名單。
6. 每筆歸入「所屬交易日」，合併成以個股為單位的當日清單。
7. 使用者勾選要匯出的個股，選擇通用匯出，或進入「逐檔快速加入」模式，在富邦e點通裡逐檔輸入代號。
8. 精簡欄位永久保存；原文 7 天後自動刪除。

## 功能需求（階段 1）

階段 1 包含五組功能：入口、規則式整理、每日清單、匯出、資料保存與存取。

### F1 總入口

- 單一大文字框，可貼整段 LINE 內容（網址、memo、節錄混在一起），並可貼上或拖曳圖片，每天不超過約 20 張。
- 送出前顯示拆分預覽，使用者可以合併、刪除、修改類型。
- 網址去掉追蹤參數後去重；同一則新聞只處理一次，多人貼同一篇時合併，貼入者暱稱選填。
- 抓不到內文時標示「抓取失敗」，允許改貼文字補上，不能讓整筆消失。

### F2 規則式整理（階段 1 不使用 AI 摘要）

- 個股辨識：用證交所與櫃買中心的官方名稱與代號清單比對；比對不到或有歧義的標「待確認」，由人處理。
- 重點句：直接擷取原文中提到該個股、且含關鍵字的句子，每檔每則來源最多 2 到 3 句。關鍵字例：漲價、訂單、營收創高、合作、供不應求、擴產、轉型、調升目標價。
- 標籤：固定清單，管理員可增修；標籤只描述新聞在講什麼，不代表利多或利空。
- 國際大廠：比對全球市值前 100 名的公司名單（名單可由管理員維護），並寫出合作對象的公司名稱。
- 沒有指名個股的內容存成「未歸屬個股」，可手動補。
- 圖片先用免費的文字辨識；辨識不準時，可人工貼上文字補正。
- 保留日後接上 AI 摘要的開關。

### F3 每日清單

- 底層一列＝一檔股票 × 一則新聞；畫面預設以個股合併，顯示被幾則新聞提到、標籤、各則標題與重點句。
- 不做利空過濾：所有被提到的個股都列入，也都可以匯出。
- 標籤與對應個股可由人修正，並記錄是系統判斷或人工修改。
- 欄位：個股名稱、代號、新聞標題、重點摘要（重點句加標籤）、合作對象公司。

### F4 匯出

- 通用格式：純代號文字檔（一行一個）、CSV（代號、名稱）、一鍵複製。
- 可選「只匯出已勾選」或「當天全部」；勾選狀態只存在各人的瀏覽器。
- 超過 60 檔時自動拆成 A、B 組，依被提到的新聞數由多到少排序；群組以日期命名，例如 1024-A。
- 逐檔快速加入模式：依序以大字顯示代號與名稱，可標記「已加入」，協助在富邦e點通逐檔輸入。

### F5 資料保存與存取

- 永久保存：股票代號與名稱、標題、原始網址、重點句、標籤、所屬交易日、貼入者暱稱、判斷來源（系統或人工）。
- 原文只保留 7 天後自動刪除；圖片辨識完即刪；標示為內部資料的券商 memo，原文處理當天就刪。
- 存取：群組通關密碼或邀請連結；不被搜尋引擎收錄；沒有公開分享連結；管理員可刪除任何一筆。

## 資料模型與所屬交易日

底層存最細的一層「提及紀錄」，畫面再往上合併成個股清單；每筆都帶「所屬交易日」，這個欄位決定清單、匯出、歷史與累計統計。

| 欄位 | 說明 |
|---|---|
| 股票代號、股票名稱 | 來自官方清單比對，不讓程式憑印象填；比對不到標「待確認」 |
| 市場別 | 上市、上櫃等，來自官方清單 |
| 新聞標題、來源、原始網址 | 網址已去除追蹤參數 |
| 重點句 | 每檔每則來源最多 2 到 3 句原文 |
| 標籤 | 固定清單，只描述內容 |
| 合作對象公司 | 比對全球市值前 100 名名單後寫出公司名稱 |
| 所屬交易日 | 這筆資料要給哪一天開盤使用，規則見下 |
| 新聞發布日、貼入時間 | 與所屬交易日分開記錄，不要混在一起 |
| 貼入者暱稱 | 選填 |
| 判斷來源 | 系統判斷或人工修改 |
| 狀態 | 正常、待確認、未歸屬個股 |

原文另存暫存區（內容、類型、貼入時間、到期時間），7 天後自動刪除，不屬於永久資料。

所屬交易日規則：看「貼進來時，下一次開盤是哪一天」。

- 交易日 09:00 前貼入，歸當天（例如早上的外電整理）。
- 交易日 09:00 之後貼入（含盤中與收盤後），歸下一個交易日。
- 週五晚上、週末、假日貼入，歸下一個開盤日，通常是週一。
- 每一筆都可以手動修改所屬交易日。
- 休市日預先載入證交所公布的行事曆；颱風假等臨時休市以手動修改處理。

## 券商整合現況

目前能確認的是富邦e點通有雲端「自選同步」，但還沒有任何已驗證的方式，能把網站產出的清單批次送進去。

- 發起人用富邦e點通手機 App：自選有 10 個群組，每組可放 60 檔；1 組放持股，其餘多是每天的新聞標的，不同天存不同組。
- 自選報價頁右上的「自選同步」有「自選股上傳」與「自選股下載」，點了直接執行，不會要求選檔案。
- 下載前的彈窗說明：手機群組 1 到 10（每組前 60 檔）會被替換成曾在e點通、e01、e+ 上傳的自選股；從未上傳過的人請取消，避免手機自選被清除。意思是同步為整批覆蓋，而且每組只同步前 60 檔。任何測試前先截圖備份手機自選。
- 富邦官網的交易平台介紹列有電腦軟體 e01、e+ 電腦版、HTS2，以及 API 程式交易。電腦版是 Windows 軟體；發起人的 Mac mini（M6）要跑電腦版得用虛擬機，相容性未知。
- 沒有查到官方說明，證明電腦版可以匯入自選股檔案，也沒查到電腦版與手機自選互通的細節，這兩點都未驗證。
- 網站無法直接寫入富邦雲端。若電腦版可行，流程會是：網站匯出 → 電腦版匯入 → 上傳 → 手機下載。
- 其他朋友的券商與軟體未知，需要先在群組做調查，再決定要做哪幾家的專用格式。

## 非功能需求與限制

第一版必須零成本、只限群組使用，並且用「少存原文」降低版權與合約風險。

- 成本：整個網站維持免費，使用免費額度的雲端空間與資料庫（額度與條款要在開發前查證）。第一版不用付費的 AI API；Claude Pro 訂閱不含 API 用量，API 另外計費。
- 架設與維護：自己架在雲端服務上，由發起人當管理員、持有帳號。需要有後端（抓網址內文、文字辨識、存資料庫、定時刪除原文），單純的靜態頁面不夠。
- 規模：約 30 位使用者；依已貼過的資料估算，每天約 45 到 60 檔個股，圖片不超過 20 張。
- 版權與隱私：原文只保留 7 天；券商 memo（例如國泰那份寫明禁止轉發）處理當天就刪原文；只有輸入群組密碼才能進入，不被搜尋引擎收錄。這不是法律意見，上線前請自行評估。
- 可靠度：抓不到網址內文時不能讓整筆消失，必須標示並允許補貼文字。
- 可擴充：匯出做成可以逐家新增格式的結構；AI 摘要保留開關。

## 階段 2 與階段 3 需求

階段 2 需要外部股價資料，階段 3 取決於富邦電腦版能否匯入；兩者都先記錄，暫不開發。

### 階段 2

- 漲停續看清單：每個交易日收盤後，用交易所公布的當日收盤資料，比對當天清單裡的個股；只算「收盤漲停」（收盤價等於漲停價），自動產出隔天要看的清單，匯出時單獨一組。可以手動增減，並記錄是系統判斷或人工修改；每日漲停紀錄保留。官方資料何時可取得、怎麼取得，開發前要確認。
- 累計統計：同一檔股票連續幾個交易日被提到；週末與休市日不算中斷，需要交易日曆；底層每日提及紀錄永久保留，之後可以和漲停紀錄一起統計「新聞標的漲停後，隔天續漲的比例」。

### 階段 3

- 富邦專用匯入格式：取決於電腦版（e01 或 e+）是否支援匯入檔案，以及電腦版上傳後，手機e點通下載是否同步成功。
- 其他券商：等群組調查（用哪家券商、哪個軟體）完成後，再排優先順序。

## 未決事項與風險

最大的未知數是「怎麼把清單批次送進手機自選」，目前階段 1 先用逐檔快速加入模式頂著。

| 事項 | 為什麼重要 | 目前狀態 |
|---|---|---|
| 富邦電腦版能否匯入檔案、能否同步到手機 | 決定階段 3 做不做得成 | 未驗證；虛擬機測試與客服預檢先擱置 |
| 自選同步是整批覆蓋 | 誤按「下載」可能清掉手機群組，包含持股 | 任何測試前先截圖備份；階段 3 設計要保護持股群組 |
| 每組只同步前 60 檔 | 超過會被截斷 | 階段 1 自動拆 A、B 組 |
| 其他朋友的券商與軟體 | 約 30 人，券商未知 | 待在群組發一個簡單調查 |
| 免費額度與條款 | 免費額度可能變動 | 開發前查證 |
| 報紙照片的文字辨識準確度 | 免費工具可能不準 | 需實測，可人工貼文字補正 |
| 規則式摘要品質 | 可能不如 AI 摘要 | 保留 AI 開關；人可修正 |
| 官方股價資料的取得方式與時間 | 階段 2 的漲停判斷要用 | 待確認 |
| 版權與合約 | 券商 memo 與報紙全文 | 少存原文；非法律意見，上線前自行評估 |

建議的下一步：在新的對話裡，把本文件交給 Claude，從階段 1 開始實作；第一件事是選定免費的雲端服務並查證它的額度。

## 附錄：真實輸入樣本與已定案決策

### 真實輸入樣本的類型

來自發起人貼過的資料，開發與測試時請以這些為準。

- 新聞網址：經濟日報（udn）、工商時報（ctee）、鉅亨網（cnyes）、mtkstock 等，常帶分享追蹤參數與 App 推廣文字。
- 券商 memo 純文字：國泰證期研究部、永豐金的評等調整、TPCA memo、美系外電綜合整理；一份常含多檔個股。
- 報紙版面照片（工商時報）。
- 朋友自己節錄的重點段落。
- 沒有指名個股的內容，例如黃仁勳的談話。

### 已定案決策

1. 約 30 人共用一份當日清單，群組密碼進入，不做完整帳號系統。
2. 單一總入口，網址、文字、圖片混貼，送出前先預覽確認。
3. 資料模型：一列＝一檔股票 × 一則新聞，畫面以個股合併；股票代號用官方清單比對，不確定標待確認。
4. 要寫出國際大廠合作對象的公司名稱，範圍為全球市值前 100 名。
5. 系統不判斷利多或利空，所有被提到的個股都列入。
6. 所屬交易日：交易日 09:00 前貼入歸當天，其餘歸下一個開盤日，可手動修改。
7. 匯出超過 60 檔時自動拆 A、B 組，依被提到新聞數排序，群組以日期命名。
8. 第一版用規則式整理，不用 AI 生成摘要，保留日後開關。
9. 永久只存精簡欄位；原文只保留 7 天；圖片辨識完即刪；網站只限群組使用。
10. 網站維持免費，由發起人自己架設與管理。
11. 分階段：先做階段 1；虛擬機測試與客服預檢暫緩；不匯入過去 LINE 的資料。
12. 想要的後續功能：收盤漲停續看清單、連續被提到的累計統計。
